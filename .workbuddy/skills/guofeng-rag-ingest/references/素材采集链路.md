# 素材采集链路

阶段 1 的可复现步骤。目标是拿到**三个层次**的证据：元数据（热度）、画面（形态与技法）、文字（作者与观众的表述）。

## 一、B 站视频（最常用）

### 1. 元数据

```
https://api.bilibili.com/x/web-interface/view?bvid=<BV号>
```

取 `title / owner.name / owner.mid / pubdate / duration / aid / cid / desc / stat`（`stat` 含 view/like/coin/favorite/share/reply/danmaku）。`desc` 常为空，不要指望简介。

### 2. 弹幕（信息密度最高，必取）

```
https://api.bilibili.com/x/v1/dm/list.so?oid=<cid>
```

返回的是 **raw deflate**，需 `zlib.decompress(data, -15)` 解压（先试 -15，失败再试无 wbits）。解压后是 XML，用正则提取：

```python
re.findall(r'<d p="([\d.]+),[^"]*">([^<]*)</d>', text)
```

`p` 的第一段是秒数。按时间排序即得时间轴——**这是抽帧的采样依据，也是判断剪辑点、机制规则、社区话术的主要来源**。

### 3. 评论区（拿"最火"与机制细节）

```
https://api.bilibili.com/x/v2/reply?type=1&oid=<aid>&sort=2&ps=20&pn=1
```

`sort=2` 按热度。顶层评论常少于 20 条，但楼中楼里有高赞长回复，机制说明往往在那里（例："喝酒是 LB+Y，也就是说你要按住防御键的……"）。

### 4. 封面

页面 HTML 里取 `i*.hdslb.com/bfs/archive/<hash>.jpg`，必须带 `Referer: https://www.bilibili.com/`，否则 403。封面常含标题设计与关键特效字，值得单独读图。

### 5. 视频本体与抽帧

```bash
# 注意：pip 可能装在 Python312 而 python 指向 3.13，用全路径
PY312="C:/Users/59784/AppData/Local/Programs/Python/Python312"
"$PY312/python.exe" -m yt_dlp --list-formats "<URL>"        # 先看可用格式
"$PY312/python.exe" -m yt_dlp -f "30080+30280" -o "video.mp4" "<URL>"
```

- `30080` = 1080P 视频，`30280` = 音轨。**4K、1080P60 需大会员**，1080P/30 免登录可拿，读内容已足够。
- 音视频可能不合并（缺 ffmpeg 时），抽帧只用视频流，无需强求合并。
- ffmpeg 从 `imageio_ffmpeg` 取路径：`"$PY312/python.exe" -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())"`

抽帧：

```bash
"$FF" -loglevel error -ss 00:48 -i video.f30080.mp4 -frames:v 1 -q:v 2 -y f09.jpg
```

**按弹幕时间轴选点**，不要等间隔抽。九宫格拼图用 `concat` + `tile`：

```bash
"$FF" -y -i f01.jpg ... -i f09.jpg \
  -filter_complex "[0:v]scale=560:-2[v0];...[8:v]scale=560:-2[v8];[v0]..[v8]concat=n=9:v=1[s];[s]tile=3x3[out]" \
  -map "[out]" -q:v 3 sheet1.jpg
```

注意：**没有 `x9` 滤镜**，`n×m` 网格只能靠 `tile`。拼接失败时先看是不是滤镜名写错。

### 6. 界面文字

游戏/影视里的 UI 面板（武器属性、技能描述、装备提示）是**官方一手文案**，价值高于任何二手解析。定位方法：先按弹幕时间点取帧，若为黑场则前后各扫 ±2 秒（0.4 秒一帧），找到 UI 帧后 `crop` 放大面板区域再读图。

## 二、网页与文献

- 检索时用 `freshness` 限定时间窗（艺术创造轨必须"最新"）；需要特定站点用 `allowed_domains`。
- 权威层级排序：一手原典·考古报告 ＞ 学术论文 ＞ 博物馆/官方机构 ＞ 百科 ＞ 媒体 ＞ 自媒体。**艺术创造轨反过来看时效与传播量**。
- 站内搜索页（如 `search.bilibili.com/all?keyword=`）可抓，但结果杂且依赖 JS；关键词要加限定词（"道具 复原 考据"优于"影视"）。
- 同一批结果里若多个站点文本逐字相同，是**伪多源**，不能算互证。判据：派名、BOSS 名、数值是否互相矛盾。

## 三、踩坑清单

| 现象 | 原因 | 处理 |
|---|---|---|
| `pip install` 成功但 `python -c "import yt_dlp"` 失败 | pip 与 python 属不同版本 | 用 `python -m pip` 或直接调对应版本的 python.exe |
| pip 直连超时 | 网络 | 加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 弹幕 XML 是乱码 | raw deflate | `zlib.decompress(data, -15)` |
| 封面 403 | 缺 Referer | 加 `-H "Referer: https://www.bilibili.com/"` |
| 4K/60fps 拿不到 | 需大会员 | 降级 1080P/30，不影响读内容 |
| AI 总结接口返回错误码 | 需登录 | 跳过，改用弹幕+评论自行归纳 |
| 评论接口只返回 3 条 | 接口限制 | 读楼中楼，或换 `pn` 翻页 |
| 拼图滤镜报错 | 用了不存在的 `x9` | 改 `concat` + `tile` |
| 抽到的帧全黑 | 时间点落在转场黑场 | 前后 ±0.5 秒补扫 |

## 四、素材留存
