# B站素材库

> 渐进式披露网络素材库。本仓库按「站点 → 关键词 → 视频 → 素材切片」逐级下钻。
> 读取规则：先看本总览，需要时再进入具体关键词目录，避免一次性加载海量内容。
> 
> 访问者须知：你是访客 LLM，用 `list`/`cat` 逐级浏览并判断是否命中。
> 命中不足需要抓取时，先读下文的工具与入库纪律，再动手。

## B站 缓存目录树（递归语义树）

只有**两种节点**：

- **分支节点**（导航）：只放一份同名摘要 md + 子目录，不存任何素材。
- **叶子节点**（BVID）：放该视频的元信息与素材；素材可分子目录（`肖像/`、`帧/`），但**不再建 md**。

```
B站/
├── B站.md                        ← 站点摘要（分支）
└── <关键词>/                      ← 分支：关键词
    ├── <关键词>.md                ← 摘要
    ├── <分组>/                    ← 分支：语义类目
    │   ├── <分组>.md              ← 摘要
    │   └── <实体>/                ← 分支：实体
    │       ├── <实体>.md          ← 摘要，兼登记别名
    │       └── <BVID>/            ← 叶子：视频
    │           ├── <BVID>.md      ← 元信息 + 素材清单（叶子内唯一 md）
    │           ├── cover.png      ← 素材
    │           ├── 肖像/          ← 素材容器（无 md）
    │           ├── 帧/            ← 素材容器（无 md）
    │           └── 其他素材/       ← 同上，按需
```

上面是**结构**，不是现有内容。当前缓存以 `library/B站/` 的实际目录为准；本节只负责说清每一层该长什么样。

**当前关键词**：

| 关键词 | 摘要 |
|---|---|
| 影之刃零 | `影之刃零/影之刃零.md` |

- **分支摘要**只写「这是什么 + 子项清单」，不写内容本身，靠下钻获取。
- **叶子 md** 除元信息外兼作素材清单（已抓哪些、几张），读它即可判断，不必 `list`。

**下钻纪律**：

- 一层只读一个与目录**同名** `.md` 摘要，再决定是否下钻（满分名规则）。
- **摘要层止于叶子**：分支层各有一份同名 md；叶子内部的 `肖像/`、`帧/` 是素材容器，不建 md。
- **视频叶子物理唯一**：同一视频同属多个实体时，只在归属最深/最主要的实体下落一份，其他实体在摘要里写引用，不复制。
- 抓回后若与既有实体同义 → 并入既有实体目录并登记别名，**不新建分裂目录**。
- **建库**：新关键词/实体在所属分支下建目录，放与目录同名的摘要 md。
- **视觉如实**：切片的遮挡/UI 状态如实标注，不贴分。
- 素材实体（封面、抽帧、切片）不入 git；各级 `*.md` 摘要与工具入库。

## 本站点工具（scripts/fetch.py）

调用时在技能根执行，`scripts/fetch.py` 为命令式工具（只执行、不做命中/归并判断，判断由访问者 LLM 自己决定）。

工具是设备不是素材，放在技能根的 `scripts/`（与 `library/` 平级），不进 `library/` 的数据树。

| 命令 | 作用 | 是否落盘 |
|---|---|---|
| `status [--json]` | 盘点全库：站点/关键词/实体/视频/封面/帧 + 工具可用性。**不联网、不依赖 httpx** | 否 |
| `search <关键词>` | 只搜索，打印视频列表 | 否 |
| `fetch --bvid <BVID>` | 只落这一条到 `_inbox/B站/<BVID>/`，**归位由你判断** | 是 |
| `fetch --keyword <词>` | 搜索并落整页（默认 8 条）到 `_inbox/B站/<词>/<BVID>/` | 是 |
| `cover <BVID>` | 下载单视频封面到其目录 `cover.png` | 是 |
| `frames <BVID> --n N` | 匿名拉流抽帧到 `帧/` | 是 |

调用示例：

```
python scripts/fetch.py status
python scripts/fetch.py search 影之刃零
python scripts/fetch.py --bvid BV17zsd6nE1Y fetch
python scripts/fetch.py --keyword 影之刃零 --page-size 3 fetch
python scripts/fetch.py cover BV17zsd6nE1Y
python scripts/fetch.py frames BV17zsd6nE1Y --n 4
```

说明：

- 搜索/封面/拉流全部**匿名可用**（内部走 wbi 签名 + buvid3 指纹绕过风控）。
- `search` 用位置参数传关键词；`fetch` 用 `--keyword` 或 `--bvid`，两者可同时给。`--bvid` 不搜关键词，只要一条时更省。
- `--bvid` 走 `x/web-interface/view`，该接口匿名返回的 `tname` 常为空，所以这样落的 md 通常**没有「分区」行**；要分区就用 `--keyword`（搜索结果带 `typename`）。空字段一律不占行，不写 `**分区**: ` 这种空壳。
- 多条 BVID 用逗号分隔（中英文逗号都认）：`--bvid BV1xx,BV2xx`。某条取不到会跳过并单独说明，其余照常落盘。

### 从便宜到贵

从本地到联网，按成本递增走，够用就停：

| 级 | 命令 | 花什么 | 能看到什么 | 什么时候走 |
|---|---|---|---|---|
| 0 | `status` | 不联网，只读目录 | 全库盘点 + 工具可用性 | 进来先看一眼，可能根本不用抓 |
| 1 | `search <关键词>` | 一次搜索，不落盘 | 8 条：BVID / 标题 / 播放 / UP | 先确认有没有、值不值得 |
| 2a | `fetch --bvid <BVID>` | 一次详情请求，只落 1 条 | 标题 / UP / 播放 / 描述 / 时长（无分区） | 第 1 级已选定某条，只沉淀它 |
| 2b | `fetch --keyword <词>` | 一次搜索 + 落整页（默认 8 条） | 每条：描述 / 分区 / 时长 / 封面URL | 要成批看这一块内容 |
| 3a | `cover <BVID>` | 下载 1 张图 | 一张封面静帧 | 只想知道"长什么样" |
| 3b | `frames <BVID> --n N` | 拉流 + ffmpeg 抽帧 | N 张均匀帧 | 要看动作、服饰、镜头 |

`cover` 与 `frames` 并列，不是先后。只要一条就走 2a——2b 会顺手落 7 条你用不上的。

### 搜不到的时候

关键词是这里唯一容易白跑的一步。三种真实踩过的样子：

| 现象 | 实例 | 处理 |
|---|---|---|
| 同音字写错，零命中 | 搜「沐筱奎」返回 8 条无关视频 | 换同音字「沐小葵」，命中 8 条全部相关 |
| 多义词被稀释 | 搜「影之刃零 魂」，8 条里 5 条是「类魂 / 黑魂 / 铸魂材料」 | 换角度搜「影之刃零 主角」 |
| 角色名跨作品撞车 | 光搜角色名会混进别作 | 关键词固定带作品名 |

判据：**命中率不到一半就换词，别在同一关键词上翻页**。翻页只是把不相关的内容拉得更多。

封面是 UP 主自选的二手素材，可能是二次加工（贴纸、拼图、同人图），不是官方设定图。写进摘要时要注一句来源，别让人当官方人设用。

## 归类与归位（由你判断）

`fetch` 只把视频落到暂存区，**不替你做分组**。两种落点：

- `--keyword`：`library/_inbox/B站/<关键词>/<BVID>/`（多一层关键词，方便成批辨认来源）
- `--bvid`：`library/_inbox/B站/<BVID>/`（没有关键词层）

归位判据：

1. **先看现成的**：`list` 该关键词下已有的分组与实体，能归入就归入，不允许同一实体出现两个名字。
2. **分组是语义类目**（`角色/`、`处决/`、`剧情/`…），从内容抽象一层，不是照搬视频标题。
3. **实体是被指涉的具体对象**（角色名、Boss 名、场景名）；一个视频指涉多个时取最主要的那个，别处写引用。
4. **起不出合适的名字就不建**：宁可先留在 `_inbox`，也不硬造一个只放一条视频的分组。

归位动作：

```
mv library/_inbox/B站/<关键词>/<BVID>/  library/B站/<关键词>/<分组>/<实体>/
```

归位后补齐沿途摘要 md（分组、实体的子项清单加上这条），并确认 `_inbox` 中该条目已清空 —— 暂存区不再是「待办」的标志。
