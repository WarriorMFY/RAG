# B站素材库

> 渐进式披露网络素材库。本仓库按「站点 → 关键词 → 视频 → 素材切片」逐级下钻。
> 读取规则：先看本总览，需要时再进入具体关键词目录，避免一次性加载海量内容。
>
> 访问者须知：你是访客 LLM，用 `list`/`cat` 逐级浏览并判断是否命中。
> 命中不足需要抓取时，先读 [`doc/arch-design.md`](../../doc/arch-design.md) 里的工具与入库纪律，再动手。


## 本站点工具（scripts/fetch.py）

调用时在技能根执行，`scripts/fetch.py` 为命令式工具（只执行、不做命中/归并判断，判断由访问者 LLM 自己决定）。

工具是设备不是素材，放在仓库外的 `scripts/`，不进 `library/` 的数据树。

| 命令 | 作用 | 是否落盘 |
|---|---|---|
| `search <关键词>` | 只搜索，打印视频列表 | 否 |
| `fetch <关键词>` | 抓取到 `_inbox`（建目录+md），**归位由你判断** | 是 |
| `cover <BVID>` | 下载单视频封面到其目录 `cover.png` | 是 |
| `frames <BVID> --n N` | 匿名拉流抽帧到 `帧/` | 是 |

调用示例：
```
uv run python scripts/fetch.py search 影之刃零
uv run python scripts/fetch.py --keyword 影之刃零 --page-size 3 fetch
uv run python scripts/fetch.py cover BV17zsd6nE1Y
uv run python scripts/fetch.py frames BV17zsd6nE1Y --n 4
```

说明：
- 搜索/封面/拉流全部**匿名可用**（内部走 wbi 签名 + buvid3 指纹绕过风控）。
- `search` 用位置参数传关键词；`fetch` 用 `--keyword`。详细参数见 `--help`。

## B站 缓存目录树（递归语义树）

只有**两种节点**：

- **分支节点**（导航）：只放一份同名摘要 md + 子目录，不存任何素材。
- **叶子节点**（BVID）：放该视频的元信息与素材；素材可分子目录（`肖像/`、`帧/`），但**不再建 md**。

```
B站/
├── B站.md                      ← 站点摘要（分支）
└── 影之刃零/                    ← 分支：关键词
    ├── 影之刃零.md              ← 摘要
    ├── 角色/                    ← 分支：语义分组
    │   ├── 角色.md              ← 摘要
    │   └── 魂/                  ← 分支：实体
    │       ├── 魂.md            ← 摘要
    │       └── BV17zsd6nE1Y/    ← 叶子：视频
    │           ├── BV17zsd6nE1Y.md  ← 元信息 + 素材清单（叶子内唯一 md）
    │           ├── cover.png        ← 素材
    │           ├── 肖像/            ← 素材容器（无 md）
    │           ├── 帧/              ← 素材容器（无 md）
    │           └── 其他素材/         ← 同上，按需
    └── 处决/
        └── 处决.md
```

- **分支摘要**只写「这是什么 + 子项清单」，不写内容本身，靠下钻获取。
- **叶子 md** 除元信息外兼作素材清单（已抓哪些、几张），读它即可判断，不必 `list`。

**下钻纪律**：
- 一层只读一个与目录**同名** `.md` 摘要，再决定是否下钻（满分名规则）。
- **摘要层止于叶子**：分支层各有一份同名 md；叶子内部的 `肖像/`、`帧/` 是素材容器，不建 md。
- **视频叶子物理唯一**：同一视频同属多个实体时，只在归属最深/最主要的实体下落一份，其他实体在摘要里写引用，不复制。
- 抓回后若与既有实体同义 → 并入既有实体目录并登记别名，**不新建分裂目录**。
- **建库**：新关键词/实体在所属分支下建目录，放与目录同名的摘要 md。
- **视觉如实**：切片的遮挡/UI 状态如实标注，不贴分。
- 缓存数据（关键词树、封面、帧）不入 git；README/工具为静态资产入库。

## 归类与归位（由你判断）

`fetch` 只把视频落到暂存区 `library/_inbox/B站/<关键词>/<BVID>/`，**不替你做分组**。归位判据：

1. **先看现成的**：`list` 该关键词下已有的分组与实体，能归入就归入，不允许同一实体出现两个名字。
2. **分组是语义类目**（`角色/`、`处决/`、`剧情/`…），从内容抽象一层，不是照搬视频标题。
3. **实体是被指涉的具体对象**（角色名、Boss 名、场景名）；一个视频指涉多个时取最主要的那个，别处写引用。
4. **起不出合适的名字就不建**：宁可先留在 `_inbox`，也不硬造一个只放一条视频的分组。

归位动作：

```
mv library/_inbox/B站/<关键词>/<BVID>/  library/B站/<关键词>/<分组>/<实体>/
```

归位后补齐沿途摘要 md（分组、实体的子项清单加上这条），并确认 `_inbox` 中该条目已清空 —— 暂存区不再是「待办」的标志。
